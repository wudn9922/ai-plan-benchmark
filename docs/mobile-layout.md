# 手機版排版規劃

主要使用情境是以直向手機比較個人 AI 訂閱方案。驗收寬度為 360、390、430 CSS px，並保留桌機版。

## 閱讀順序

1. 精簡頁首：網站名稱、資料更新摘要。
2. 四個比較分頁：訂閱方案、模型能力、程式代理、每美元價值。
3. 常用篩選：搜尋、公司、月費（適用方案頁）；其餘放入進階篩選。
4. 方案卡片／精簡表格切換：預設卡片，表格可直接到達。
5. 比較內容：價格、可用模型、三類分開計量的額度優先。
6. 點開查閱詳細限制、產品權限、資料日期與來源。

## 顯示原則

- 手機卡片單欄，不把完整桌機表格縮小塞入螢幕。
- 主要文字 16px，次要文字約 14px；數值可更大。
- 操作按鈕與表單至少 44px 高；表單字級至少 16px，避免手機輸入自動放大。
- 三類額度各自顯示；不得相加或把動態窗口簡化成固定數字。
- 精簡表格只有短資料，不放長段說明；只允許表格容器水平捲動，保留可辨識的首欄。
- 模型、代理、價值頁提供手機摘要，完整結果與來源仍可查閱。
- 中文文案、缺值、模型版本、推理模式與來源可信度保持既有資料語意。
- 頁面整體不可水平溢出，內容不能以隱藏捲軸或裁切方式掩蓋問題。

## 驗收

- 四分頁在 360、390、430px 都可操作，摘要不需要左右拖曳。
- 切換卡片／表格、展開來源、進階篩選與資料篩選正常。
- 桌機視窗仍有合理的多欄與表格閱讀方式。
- TypeScript／Vite 建置及既有資料與計算回歸測試通過。
- 以 Chromium 實際手機視窗檢查整頁溢出、觸控大小及互動。

## 實作與驗證紀錄（2026-10-17）

- 實作：Luna Max（gpt-6-luna，reasoning max）。獨立原始碼複審：Sol xHigh（gpt-6.1-sol，reasoning xhigh）。
- 預設卡片、精簡表格直接切換、底部四分頁、進階篩選與來源收合；模型分數摘要優先於覆蓋統計。
- Chromium／Playwright 檢查 360、390、430、1280px 四種寬度、四個分頁，共 16 組排版；另驗證表格固定首欄、指標說明、排序、權益狀態、完整來源與切頁回頂。
- 既有 7 項前端計算測試及 17 項 Python 資料流程測試通過；TypeScript／Vite 建置通過。
- 保留既有資料來源警告，以收合清單呈現；此輪沒有更新或裁決來源內容。
- 檢查採桌面 Chromium 模擬手機視窗，未宣稱實體 iOS／Android 裝置驗證。
